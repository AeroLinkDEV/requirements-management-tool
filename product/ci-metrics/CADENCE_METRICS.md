# Merge-cadence metrics for issue #561

This report is non-authoritative CI telemetry. It does not participate in branch protection and never executes pull-request code.

The trusted default-branch workflow `.github/workflows/ci-cadence-metrics.yml` records the before/after measurements required to evaluate the merge-ready Full-CI cadence introduced by PR #655, whose merge timestamp is `2026-08-17T12:09:45Z`.

For each merged pull request in the last 30 days it records:

- **pushes / head updates** — distinct PR head SHAs observed by the automatic Fast workflow or, before the cadence switch, by automatic pull-request Product runs;
- **pre-merge Full runs and attempts** — automatic Product `pull_request` runs before the switch plus readiness-dispatched Product `workflow_dispatch` runs after it;
- **cancelled runner time** — elapsed time consumed by cancelled jobs belonging to Product runs attributed to that PR;
- **final-push-to-merge** — time from the first automatic validation workflow trigger observed for the SHA that ultimately merged until `merged_at`;
- **Full runs per merge** — the pre-merge Full count, reported per PR and as before/after median/p95/max.

The push timestamp is deliberately workflow-trigger based. GitHub's PR API does not expose a separate authoritative "push occurred at" timestamp, while the automatic Fast/Product trigger is generated by that head update. The report names this measurement source instead of substituting commit author time, which can predate the actual push.

The collector queries only GitHub metadata using `contents: read`, `actions: read`, and `pull-requests: read`. It does not access persistent PostgreSQL 54329 or `product/.local`, and its artifact is measurement only. The protected `Report what this run validated` context remains the sole merge authority.
