# Requirement-hierarchy policy-to-consumer matrix

Status: current characterization inventory for issues #702/#703/#704 (Slices 1-3 of #697). This is an evidence artifact,
not a policy change. It records the behavior in the three-level ladder that exists today: `System`, `HighLevel`, and
`LowLevel`. The mutation authority is the server/domain/persistence seam named in each row; the consumer column
names the downstream API, client surface, or release projection that must continue to agree with it.

The matrix is intentionally maintained as a current inventory. A later configurable-policy slice must update the
affected row, preserve the legacy/default contract here, inventory every consumer, and test at least one
non-default configuration. No later slice may treat this file as permission to silently change the defaults.

## Deferred configurable-policy contract

The current/default answers above are the baseline contract. The later configurable slices named by #697 must
update this matrix as part of each change, identify the new server mutation authority and every API/client/readiness
consumer, preserve a documented legacy/default value, and add at least one test using a non-default configuration.
That requirement applies to levels, prefix allocation, upstream/derived rules, downstream/readiness gates, coverage,
controlled output, test-change discipline, and review-subject routing if any of them become configurable.
