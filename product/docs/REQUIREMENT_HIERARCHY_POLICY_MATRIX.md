# Requirement-hierarchy policy-to-consumer matrix

Status: current characterization and readiness inventory through issue #705 for issues #702/#703/#704/#705/#713 (Slices 1-4 of #697 plus configured-policy routing). This is an evidence artifact,
not a policy change. It records the behavior in the three-level ladder that exists today: `System`, `HighLevel`, and
`LowLevel`. The mutation authority is the server/domain/persistence seam named in each row; the consumer column
names the downstream API, client surface, or release projection that must continue to agree with it.

The matrix is intentionally maintained as a current inventory. #705 routes only the complete change-authoring,
identifier, upstream/downstream, ReqIF, enterprise-alias, generic-trace, and controlled-editing identity seams
through one project-aware resolver. Runtime storage still returns the exact legacy policy until the sole #713
activation authority is eligible; a configured graph is exercised only through a legitimate injected/test policy
seam. Every remaining consumer stays an explicit activation blocker.

Activation manifest source contract: `#702-legacy-consumers-v1` and the stable consumer identifiers in the
activation row below are the compiled readiness inventory; routed implementations register separately and cannot
flip a readiness flag in this document.
